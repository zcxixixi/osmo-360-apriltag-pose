# 双 Osmo 360 夹爪定位：问题与架构

## 1. 这次问题的根因

轨迹趋势能看懂、但左右夹爪在同一交接点相差约 12.5 cm，并不是一个单独的
“滤波参数问题”，而是几个坐标和标定问题叠加：

1. **两条轨迹曾分别从各自第一帧归零。** 这样会永久丢失两台相机真实的初始
   相对位置；之后用手动3D布局补回来，只能让画面看起来接近，不能成为测量值。
2. **墙面地图不一致。** 旧录像中两面墙曾出现重复ID；同一个ID对应两个空间
   位置时，PnP即使重投影误差很小，也可能得到错误的世界位置。生产地图现在要求
   全局唯一ID，并对重复ID直接报冲突；旧数据只能进入显式抢救/诊断路径。
3. **平面PnP存在镜像分支。** 墙面可能是任意朝向，不能只把“Z不变”当作平面。
   当前用SVD识别任意平面、IPPE生成双解，再用IMU和时间连续性选择分支。
4. **左右外参曾按left/right名称绑定，而不是按相机序列号绑定。** 相机换边后会把
   `T_camera_base`用反，直接造成夹爪水平/竖直、朝向和TCP端点错误。现在导出前
   必须同时核对相机序列号、标定文件、source view和mount revision。
5. **相机原点、夹爪底座和TCP曾在显示层混用。** 模型看起来对，不代表训练数据
   中的夹取中心正确；所有输出必须走同一条显式刚体变换链。

因此，视频清晰度不是这次相对位置错误的主因。清晰度主要影响检测覆盖率；共同
世界地图和相机到夹爪外参决定左右轨迹能否在真实空间重合。

## 2. 端到端架构

```text
双路 DJI OSV
  │
  ├─ djmd工厂内参/畸变/双镜头外参/IMU
  ├─ PanoForge remap + masked merge（关闭增稳）
  └─ 统一2:1全景、帧率、时间戳
          │
          ├─ 音频三次敲击同步 + capture UUID
          │
          ├─ 球面转多路局部透视
          ├─ AprilTag角点检测/光流跟踪
          ├─ 任意平面IPPE + 非共面PnP
          ├─ IMU姿态桥接 + guarded visual re-anchor
          └─ T_world_camera + 测量状态/质量审计
                    │
                    ├─ T_camera_base（按序列号和安装版本）
                    ├─ T_base_tcp（CAD/URDF）
                    └─ T_world_tcp
                              │
                              ├─ Kalman + RTS位置平滑
                              ├─ 四元数连续化 + SLERP
                              ├─ 开合角/夹宽
                              └─ MP4、CSV、JSON、NPZ、UMI Zarr
```

## 3. 视频预处理与同步

- `.OSV`不是简单改扩展名。系统从`djmd`读取工厂标定，生成两颗镜头的
  `xmap/ymap`和融合蒙版，输出真实2:1等距柱状全景。
- 增稳关闭，避免相机运动被软件抵消；IMU单独保留给姿态分支选择和短时恢复。
- 双机画质统一到共同真实规格。例如一台50 fps、一台59.94 fps时，采用50 fps，
  不把50帧人工插成60帧。
- 两台相机内部时钟只用于粗配对。最终用开头/结尾三次敲击的音频波形做亚帧同步，
  并给同一次采集生成同一个UUIDv4。

## 4. 世界Tag地图与自动墙面标定

- 正式采集使用两面墙全局唯一的Tag ID；每个Tag保存四个世界坐标角点、实际黑色
  编码区边长、坐标系名称和地图SHA256。
- 算法不再硬编码Tag必须是200 mm，而是读取地图声明的实际尺寸并检查四条边。
- 两面墙的相对旋转和平移可以从一段同时观察两面板的标定视频中自动估计，使用
  固定尺度SE(3)优化；不需要手工逐个输入Tag间距。
- **仍必须知道至少一个真实尺度**，通常就是Tag实际边长。单目视频无法凭空恢复
  米制比例。如果面板移动、Tag尺寸改变或相机重新安装，需要重新标定并生成新哈希。
- 单段自动结果标为`PROVISIONAL`；独立录像复核通过后才冻结为生产地图。

## 5. 每帧6DoF解算

1. 将2:1全景投影为多个局部透视视图，合并并去重角点。
2. 若角点共面，用SVD建立局部平面并运行IPPE双解；若同时看到两面墙形成非共面
   点集，则运行普通3D PnP。
3. 用重投影RMSE做基础质量门槛；用DJI IMU相对旋转、上一权威视觉锚点和跨视图
   一致性排除平面镜像解。
4. 直接多Tag视觉可以更新权威锚点；单Tag+IMU平移、光流和短时恢复具有单独状态，
   不能伪装成直接多Tag测量。
5. 若同一视角检测到空间上分离的同ID实例，生产路径立即标记
   `DUPLICATE_ID_MAP_CONFLICT`，不再静默保留面积最大的一个。

主要输出是：

```text
T_world_camera
parent_frame / child_frame
translation_m / quaternion_xyzw
measurement_state / measurement_source
reprojection_rmse_px / detected_ids / tag_map_hash
```

## 6. 从相机到夹爪TCP

AprilTag墙面解算得到的是相机光学中心，不是夹取物体的位置。正式位置统一计算为：

```text
T_world_tcp = T_world_camera × T_camera_base × T_base_tcp
```

- `T_world_camera`：视觉+IMU得到的相机世界6DoF。
- `T_camera_base`：相机到夹爪底座的固定安装外参，必须按相机序列号和安装版本绑定。
- `T_base_tcp`：夹爪底座到夹取中心，来自CAD/URDF。

左右夹爪分别使用自己的`T_camera_base`，但必须使用同一份世界Tag地图。网页、审计
视频、CSV和UMI都读取同一组`T_world_tcp`数组，不允许显示层再加手动平移或旋转。

## 7. 开合角、滤波与数据状态

- 夹爪底座Tag ID 2提供局部参考，两个黄色标记提供左右关节方向；结合CAD转轴计算
  开合角和夹宽。
- 位置使用Kalman + RTS，姿态使用四元数连续化和平滑后SLERP到目标频率。
- 每帧明确区分`MEASURED_DIRECT`、`MEASURED_LK`、`RECOVERED`、`PREDICTED`和
  `LOST`。滤波让轨迹连续，但不会提高真实视觉测量率。

## 8. UMI导出质量门禁

只有以下条件同时满足才标记训练就绪：

- 左右相机序列号、外参文件、source view和mount revision匹配；
- 两路使用同一冻结世界地图及SHA256；
- 无重复ID冲突、镜像矩阵或未注明方向的变换；
- PnP RMSE、可信覆盖率、最长失锁和同步误差通过阈值；
- 两侧TCP位于同一桌面工作空间，抓取/放置交接点通过独立任务验证；
- 长插值和纯预测帧不进入`action_valid`。

正式数据保存共同世界坐标`robot*_eef_pos/quaternion`，并额外保存
`robot*_eef_delta_from_start`供只需要局部增量的模型使用。

## 9. 当前结论

- 单路视觉姿态翻转、错误IMU拒绝和重复ID静默去重已经在算法层修复并有回归测试。
- 当前旧Demo中约12.5 cm交接误差不能靠滤波消除；它主要反映旧墙面变换和相机到
  TCP外参仍是临时标定。
- 新采集应先用唯一ID墙面完成一次自动墙间标定，再做序列号绑定的左右外参标定；
  通过独立交接点验证后，才适合规模化导出UMI训练数据。
